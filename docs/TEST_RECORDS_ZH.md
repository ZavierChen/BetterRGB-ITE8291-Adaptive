# 测试记录

## 构建测试

- 从独立暂存源码重新编译资源、第一方 C 代码和 hidapi，不复用原仓库对象文件。
- 第一方代码在 `-Wall -Wextra -Wpedantic -Werror` 下通过。
- hidapi 0.16.0 出现三个上游 strict-prototype 警告，无错误。
- 生成 PE 为 x86-64 Windows GUI，文件版本 3.6.1。

## 3.6.1 音量 Bar 回归

- 第一方代码在严格警告即错误模式下重新构建通过。
- 二进制版本资源、体积和 SHA-256 校验通过。
- 默认播放端点 ID 每秒复核，端点变化后会释放旧接口并重新绑定音量与播放峰值接口。
- 音量变化阈值仍为 0.4%，临时覆盖保持 1.8 秒；新增开始、结束和重绑定诊断日志。
- 3.6.1 候选版已安装到本机原计划任务路径并正常启动；日志确认默认播放端点重绑定成功。
- 通过将主音量暂时调整 1% 后恢复，日志确认 `volume override started` 与 `volume override ended` 均被触发。
- 自动化日志只能验证状态机，最终顶行 RGB Bar 的视觉效果仍由用户实机确认。

## 隔离目录运行测试

将候选 EXE 单独放入空目录启动，目录初始无配置和日志。程序成功：

- 枚举 `VID_048D&PID_600B` 的 MI_00/MI_01。
- 选择 Usage Page `0xFF03` 的 MI_01。
- 取得独占设备锁并进入自定义模式。
- 启动隐藏窗口、WMI Fn 监听和指标工作线程。
- 自动创建 `better_rgb.cfg`/`rgb_engine_log.txt` 的运行路径能力得到验证。

隔离测试结束时使用外部测试脚本强制终止候选进程，随后确认正式安装版的计划任务与运行进程恢复。强制终止仅用于测试夹具清理，不是推荐的用户退出方式。

## 实机功能回归

- 左 Shift、Enter 等宽键映射在修正后点亮。
- Fn+F6/F7 可调整 BetterRGB 亮度；Fn+Space 当前未适配。
- 插拔电源可切换独立配置。
- 定时休眠、输入唤醒、启动/退出过渡可运行。
- 官方控制中心与 BetterRGB 存在预期的独占冲突，退出 BetterRGB 后可恢复官方方案。
