# 后续开发路线

## P0 稳定性

- 将设备白名单拆成机型描述表，包含 VID/PID、Usage Page、接口、键位布局和能力位。
- 为 512 字节帧、过渡蒙版和键位映射增加离线单元测试。
- 增加设备断开、睡眠/唤醒、快速插拔电源和官方服务重启压力测试。
- 研究共享模式前先确认 hidapi 打开策略与厂商服务重入行为，默认继续使用独占模式。

## P1 体验

- 把灯效注册、参数定义和 UI 元数据数据化，减少单文件中的重复分支。
- 增加键盘布局预览和逐键诊断模式，便于新批次映射。
- 增加导入/导出配置及明确的配置 schema 版本。
- 对星光、雨滴、闪电继续使用连续包络和亚帧插值，避免单键闪烁。

## P2 官方协作

- 与厂商确认 ITE8291/EC 的安全刷新率、HID 协议文档和官方控制服务所有权模型。
- 将 BetterRGB 的逐帧效果作为官方控制中心可选高级引擎，而不是与其抢占。
- 为 EXE 加入可信代码签名、版本发布页和可验证哈希。
- 建立不同 BIOS、EC、键盘批次的兼容性实验室矩阵。

## 不建议路线

在没有原理图、EC 固件源码、恢复编程器和厂商授权前，不逆向修改 EC 刷新周期，不对刷写包打补丁。用户态 HID 已证明可改善观感，应优先在这一安全边界内优化。
