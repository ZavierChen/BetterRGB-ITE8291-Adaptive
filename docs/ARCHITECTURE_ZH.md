# 架构与 RGB 控制流程

```text
Win32 UI / Fn 热键 / 电源事件
              |
              v
        配置与模式状态
              |
              v
       单个灯效工作线程
              |
              v
      512 字节逻辑 RGB 帧
              |
              v
 Touch Bar 覆盖 + 过渡蒙版 + 亮度
              |
              v
        send_frame 串行化
              |
              v
 hidapi -> Windows HID -> ITE 048D:600B
              |
              v
           键盘 LED
```

## 并发模型

UI 线程负责窗口消息与设置；当前灯效在线程中循环生成帧；指标线程低频采集系统状态；WMI 线程订阅 Fn 事件。`g_deviceLock` 串行化 HID 初始化和写入，模式切换先请求旧线程停止，再重新进入自定义模式并启动新线程。

## 帧率与节奏

灯效线程调用统一节拍器，根据目标发送上限等待。若 HID 写入持续变慢，引擎会记录慢帧并降低有效发送频率，恢复稳定后逐步回升。

## 电源与休眠

插电和电池各自保存模式、亮度、目标 FPS 及 Touch Bar 参数。电源状态改变时应用切换配置。用户无输入达到设定时间后，`send_frame` 在提交前应用休眠熄灭蒙版；恢复输入时按同一过渡体系重新点亮。

## 失败恢复

HID 发送失败会触发重连请求。程序退出时先执行可选的熄灭过渡，再释放 HID 句柄。官方服务若重新占用设备，本程序可能无法打开接口，这是当前独占控制模型的预期限制。
